一间好自习 · 工作台使用说明

适用于校园自习空间布局设计与自动验收工作台。全部样例均为模拟场景，不代表实测、真实部署或用户试验。产品限定矩形房间、单门、最多3件家具、1—12座和0°/90°桌椅朝向；单位均为米。通道参数不是消防认证。

1. 打开工作台

双击项目目录中的 一键打开工作台.cmd。脚本会检查本地 Node、AGH 与产品服务并打开浏览器。也可打开 http://127.0.0.1:4319/。不要双击 workbench.html；file:// 页面无法安全连接本地任务服务。启动失败时按提示查看项目 logs/workbench-launch.log，确认本机服务与 AGH 配置后再启动；不要在页面输入或保存模型密钥。

2. 先熟悉样例或查看历史回放

  1. “载入6座例子”载入模拟草稿，不会运行任务；输入仍可编辑。
  2. “查看已验证6座示例”通过只读 GET 载入已有 normal 成功任务的输入、结果和资产，是历史回放；它不会发起本次模型调用，也不能当成本次执行证据。
  3. 要查上次任务时点“恢复上次任务”。任务运行时输入与快速按钮会锁定，避免串入旧结果。

3. 输入房间、门与家具

宽度沿 X、深度沿 Z，原点为西南角。平面画布南墙在上、北墙在下。南/北墙门偏移从西端沿墙量起；东/西墙从南端沿墙量起。门偏移不得留空。家具表格中的 X/Z 是中心，宽/深/高均以米计；最多3件且须在房间内。添加、编辑或删除家具会同步到高级 JSON，空数值不会被当作零。高级 JSON 适用于检查/修正输入；修复语法错误后可重新提交。

4. 开始真实 AGH 任务

  1. 确认模拟场景标识、房间、门、座位、家具和需求文本。
  2. 点“通过 AGH 生成”只提交一次。实际设计会建立真实 AGH 任务；模型为配置的 gpt-6-astra，经 ToTokens Responses 接口，布局与验收由明确的产品代码工具执行。
  3. 查看可见执行链、任务 ID、原生 AGH 状态和模型用量。不会用假进度代替工具调用。搜索预算内未找到并非数学上的绝对无解。
  4. 独立验收、GLB 导出及最终资产复核完成前，不把布局称为通过。只在本任务通过且 GLB 存在时启用3D。

5. 查看、下载和修改

“2D 平面”显示当前草稿或已绑定任务的房间、门、家具、桌椅与通路。“3D 旋转”打开实际导出的 GLB 本地查看器；拖动旋转、滚轮缩放，可勾选墙体与编号。下载区提供 GLB、平面 SVG、可编辑 JSON 和验收报告。改变输入会清除旧任务绑定、下载和3D入口；旧任务的记录仍保存在它自己的任务目录，不会伪装成新输入结果。

6. 测试与故障恢复

“测试故障注入与修复”只用于验证纠错流程，是测试任务；请勿将其写成正常运行。输入校验失败时看中文提示，修正门偏移、家具或 JSON 后可再次提交。服务/轮询中断时先确认本地服务在线，再按界面提示恢复同一任务；恢复不是新任务。账号、额度或不支持模型错误应先处理配置，禁止连续重试。服务恢复或新启动失败时保留原失败记录，不将其改写成成功。

7. 3—5分钟操作录制顺序

  1. 0:00—0:25 展示项目名、模拟数据声明和本地 HTTP 工作台。
  2. 0:25—0:55 点击载入6座草稿，指出这一步没有运行任务。
  3. 0:55—1:20 查看已验证历史示例，说明它是 GET 回放、不代表本次模型调用。
  4. 1:20—1:55 编辑房间/门或家具表格，指出米制、中心坐标和上限；随后载入草稿。
  5. 1:55—3:00 发起一次真实 normal 任务，拍到真实任务 ID、AGH 工具链及执行状态。
  6. 3:00—3:40 展示独立验收、比较与最终资产检查；若结果未通过，原样说明，不补拍伪成功。
  7. 3:40—4:30 打开本任务 GLB，旋转/缩放并展示下载项及可编辑文件。

异常演示可选：打开高级测试故障注入，明确标记为测试，展示 check-draft 失败反馈→按原约束修复→独立验收。实际耗时取决于网络与执行情况，不承诺一分钟完成；保留片段时间变化，不用历史回放冒充本次任务。仅使用实际录制内容，不伪造模型回应、用户试验或消防认证。
